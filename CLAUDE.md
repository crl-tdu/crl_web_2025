# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

**Not** a website. A **data-only research dataset** for the lab homepage (HTML/CSS/JS, the generator, working prompts, and scratch files have been intentionally removed — see `README.md`). The job here is to keep the dataset clean and growing as new theses arrive each year, not to render anything.

The only executable code lives under `scripts/` — small Python 3.11+ stdlib-only utilities that ingest PDFs and rebuild derived artifacts.

## Commands

All workflows go through the Makefile. From the repo root:

```bash
# Annual onboarding for one new thesis (typical: 数本/年)
make convert PDF=pdfs/2026_M_foo.pdf      # PDF → proc/txt/<file_id>.md via markitdown
make strip-toc                            # idempotent TOC stripping over all proc/txt/*.md
make scaffold FILE_ID=2026_M_foo \
              TITLE='…' TITLE_EN='…' \
              STUDENT_ID=25KMH01 \
              MEMBER_NAME='山田 太郎'      # creates dataset/research/records/<file_id>/ skeleton
                                          # AND updates dataset/members/records/<member_id>.md

# Rebuild derived artifacts (data/thesis.json, data/members.json, dataset/quality.md)
make derive

# Verify derived files are in sync with dataset/ (CI-style check; exits 1 on drift)
make check
```

`convert_thesis.py` shells out to the `markitdown` CLI; everything else is pure stdlib.

There is no test suite. `make check` is the integrity check — run it before committing dataset edits.

## Architecture

### Canonical vs derived split (most important rule)

```
SOURCE OF TRUTH (hand-curated)              DERIVED (regenerable, do not hand-edit)
─────────────────────────────────           ─────────────────────────────────────
dataset/research/records/<file_id>/    ──┐
  ├─ index.md      (manifest)            │  make derive
  ├─ summary.md    (card-facing)         │   ──────►  data/thesis.json
  ├─ detail.md     (long-form body)      │            data/members.json
  └─ assets.md     (image manifest)      │            dataset/quality.md
dataset/members/records/<member_id>.md   │
dataset/publications/records/*.md        │
dataset/keywords/records/*.md          ──┘

proc/txt/<file_id>.md   ← regeneratable from pdfs/ via `make convert`
```

**Never hand-edit** `data/thesis.json`, `data/members.json`, or `dataset/quality.md` — they will be overwritten by the next `make derive`. Edit `dataset/` and rebuild.

### Frozen historical snapshots in `data/`

Not everything under `data/` is regenerated by `make derive`. Only `thesis.json`, `members.json`, and `dataset/quality.md` are. The rest are **frozen snapshots produced by earlier generation scripts that are no longer in this repository**:

- `data/project.json` — generated 2025-06-18 from `proc/txt/*.md + thesis.json`
- `data/keywords.json` — derived from `project.json`'s keywords field
- `data/publish.json` — generated from `project/publish.md`
- `data/portfolio_research.json` — generated 2026-03-27 from `project.json`
- `data/legacy_project_index.json` — legacy index

Treat these as immutable artifacts unless you also bring back the (missing) generator. Do not try to regenerate them with the current scripts — they will not.

### Identity model

- **Primary key for research records is `file_id`, not student name.** Format: `<year>_<degree_code>_<member_id>`, where `degree_code` ∈ `{B, M, D}` (学士 / 修士 / 博士).
- **`member_id` identifies a person**; one member can own multiple `file_id`s (typical: 学士 → 修士 progression). The link is `dataset/members/records/<member_id>.md → degree_records[]`, with each entry pointing at `../../research/records/<file_id>/index.md`.
- `scaffold_record.py` keeps the member ↔ research linkage in sync — when adding a thesis, always go through `make scaffold` so `active_years`, `highest_degree`, `research_period`, and `degree_records` get bumped together.
- Doctoral records are supported by the schema but currently empty (0 D records).

### detail_quality lifecycle

Each research record carries a `detail_quality` stage tracked in `index.md`/`summary.md` frontmatter:

`skeleton` → `generic` → `draft` → `reviewed`

`make scaffold` creates a `skeleton`. `dataset/quality.md` (regenerated by `make derive`) surfaces skeleton/generic records and missing thumbnails — use it as the work queue when filling in `summary.md` / `detail.md` bodies.

### YAML frontmatter dialect

`scripts/build_derived.py` ships a **custom minimal YAML parser** (no PyYAML dependency). Supported only:

- scalar `key: "value"` / `key: value` / `key: 123` / `key: null` / `key: []`
- block sequence of scalars (`key:\n  - "a"\n  - "b"`)
- block mapping (`key:\n  inner: "v"`)
- list of mappings (used by `degree_records:`)

If you introduce multi-line scalars, anchors, flow mappings, or unquoted strings that look numeric, `make derive` will silently mis-parse. When extending frontmatter, mirror an existing field's shape and run `make check` to confirm round-tripping.

### Image asset conventions

- `proc/img/` — thumbnails and selected representative images (referenced from records)
- `proc/img_all/` — every extracted page image (search corpus)
- `assets.md` per record declares expected paths; `make derive` flags missing thumbnails into `dataset/quality.md`.

## Operational notes

- The current branch is a session branch (`session/YYYYMMDD-…`), not `main` — keep it that way per the user's global rule.
- `.gitignore` excludes `*backup` and `.DS_Store`. Generated `*backup` files (e.g. from PDF conversion) are not meant to be committed.
- `data/` and `dataset/quality.md` SHOULD be committed alongside the canonical changes that produced them — they're derived but versioned so consumers can read them without running Python.
